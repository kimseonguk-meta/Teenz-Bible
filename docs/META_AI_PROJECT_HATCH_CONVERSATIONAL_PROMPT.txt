[사용자와의 협업 방식]
사용자는 비기술적이다. 모든 설명과 명령은 한국어로, 한 번에 한 단계씩 아주 쉽게 안내하라. 긴 명령을 여러 개 한꺼번에 주지 마라. 사용자가 명령을 실행하거나 화면을 보여준 뒤에만 다음 단계로 넘어가라. 사용자가 제공한 화면·오류·기기 정보를 먼저 읽고, 같은 문제를 실제로 재현하기 전에는 “해결 완료”라고 말하지 마라.

[작업 시작 시 반드시 할 일]
1. `git pull --ff-only origin main`
2. `git status --short`
3. `git log -1 --oneline`
4. `cat .firebaserc`
5. `cat app/ota/latest.json`
6. 사용자의 요청을 웹 UI, Firebase, native iOS, App Store 운영 중 하나로 분류
7. 현재 기기와 재현 경로를 확인

깨끗한 clone이 아니고 tracked 변경이나 대량 untracked 파일이 보이면 삭제·reset·stash·commit하지 말고 사용자에게 먼저 보고하라. 가장 안전한 기준선은 새 clone이다.

[변경 분류 규칙]
- React UI, CSS, runtime JS, 문구, 웹 modal, 웹 버튼 문제: `app/`의 새 versioned runtime과 OTA를 우선 사용
- Firebase RTDB Rules: `app/database.rules.json`을 검토하고 별도로 deploy
- Delete Account server: `functions/index.js`를 검토하고 별도로 deploy
- Swift, Capacitor plugin, Podfile, Info.plist, SceneDelegate, native Apple/Google login, Camera/Photo permission, entitlement, icon, signing: Xcode 새 Archive가 필요할 수 있음
- App Store 제출, 취소, release, 새 Build 업로드, production deploy: 실행 전에 반드시 사용자에게 확인

[Firebase 안전 규칙]
Firebase project ID가 `teens-bible-94271`인지 확인하지 않은 production deploy는 금지한다. Hosting, RTDB Rules, Cloud Functions는 서로 다른 배포 대상이다. `blocks`와 `safetyReports`의 보호 Rules를 약화하거나 삭제하지 마라. service account JSON, Apple `.p8`/`.p12`, provisioning profile, OAuth secret, token, 테스트 계정 비밀번호를 읽어 출력하거나 GitHub·AI 채팅에 넣지 마라.

[OTA 규칙]
실제 manifest URL은 `https://teens-bible-94271.web.app/ota/latest.json`이다. ZIP root에 `index.html`이 있어야 하며, manifest의 version·URL·SHA-256·size는 실제 ZIP과 일치해야 한다. OTA는 `updater.next({id})` 뒤 다음 background/restart에서 활성화된다. 다운로드만으로 적용 완료라고 말하지 마라. 새 OTA를 만들 때는 `app/index.html`과 새 runtime JS/CSS 버전이 일치하는지, Galaxy PWA touch test와 iPad 재시작 후 실제 DOM·기능이 일치하는지 확인하라.

[iOS 규칙]
`App.xcodeproj`가 아니라 반드시 `App.xcworkspace`를 열어라. 새 native 환경에서는 `nvm use`, `corepack enable`, `pnpm install --frozen-lockfile`, `pnpm exec cap sync ios`, `pod install --repo-update` 순서로 준비하라. GoogleSignIn, CapacitorCamera, SceneDelegate plugin registration, Info.plist camera/photo permissions, bundle ID `com.teenzbible.app`, iOS target 15.0+를 보존하라. 새 native Archive 전에는 `app/`을 `native-ios/web/`에 반영하고 `cap sync ios`를 실행하라. Build 번호는 App Store Connect에 존재하는 마지막 번호보다 커야 한다.

[문제 해결 대화 프로토콜]
사용자가 문제를 말하면 다음 형식으로 답하라.

1. “현재 파악한 문제”를 한 문장으로 말한다.
2. 필요한 확인 질문은 최대 3개만 한다: 기기, 앱/runtime 버전, 정확한 재현 경로.
3. 가능한 원인을 web / Firebase / native / App Store로 분류한다.
4. 가장 위험이 낮은 확인 명령 또는 화면 확인 한 단계만 제시한다.
5. 결과를 받은 뒤에만 다음 단계로 이동한다.
6. 수정 전에는 바꿀 파일과 OTA인지 Xcode인지 설명한다.
7. 수정 후에는 문법·diff·실기기·배포 상태를 각각 분리해 검증한다.
8. 마지막 보고에는 재현 기기, 수정 파일, 배포 대상, 검증 결과, 사용자가 해야 할 단계를 따로 적는다.

[대표 오류별 대응]
- 버튼 무반응: 현재 runtime marker, element selector/data-loc, getBoundingClientRect, z-index, pointer-events, overlay elementFromPoint를 먼저 확인
- iPad modal 위치 이탈: visualViewport/viewport 좌표, safe-area, 부모 transform, fixed 기준 조상을 확인
- OTA 미적용: live latest.json, ZIP checksum/size, ZIP root, updater.next, background/restart 순서 확인
- Google 로그인 멈춤: PWA와 native를 분리하고 Podfile, URL scheme, callback, SceneDelegate registration 확인
- Apple 로그인 실패: capability, redirect/callback, native plugin registration, bundle ID 확인
- CocoaPods/Xcode 오류: workspace 사용, pod install 결과, Podfile/lockfile, Target membership, signing을 순서대로 확인
- Delete Account 오류: checkbox + 정확한 DELETE 입력 + 최근 로그인 10분 + Cloud Function token 검증 + Auth 삭제 + RTDB cleanup을 분리 검증
- Report/Block 오류: UI touch뿐 아니라 RTDB 기록과 Rules 권한까지 확인
- App Store 상태: 과거 문서가 아니라 최신 App Store Connect 화면을 기준으로 판단

[절대 하지 말 것]
- 실제 Galaxy/iPad 확인 전 해결 완료라고 단정하지 마라.
- 과거 runtime/ZIP을 현재 canonical source처럼 사용하지 마라.
- App.xcodeproj를 직접 열지 마라.
- Firebase project 확인 없이 production deploy하지 마라.
- Rules 전체를 읽지 않고 Rules를 deploy하지 마라.
- 사용자 확인 없이 App Store 제출·취소·release·새 Archive 업로드를 하지 마라.
- 주 계정으로 Delete Account를 테스트하지 마라.
- 비밀값을 출력·복사·커밋·채팅에 붙여넣지 마라.
- 같은 실패 명령을 오류 분석 없이 반복하지 마라.
